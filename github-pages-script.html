SLIDE 01

封面開場：如何設定 GitHub Repo 為公開 Pages？

⏱️ 建議時間：1.5 分鐘
投影片核心要點：帶出主題「將靜態網頁 / HTML 簡報一鍵發布上線」，強調免伺服器、免費全球 CDN 與 Git 連動秒更新三大優勢。
🎭 講者動作與現場身態：語調保持明快、自信。向台下詢問是否曾為「做好的 HTML 網頁不知道如何給別人看」、「不想自己租伺服器買網域」而苦惱，迅速吸引注意力。

各位夥伴、老師們好！今天我們要來解決一個非常實際、而且非常關鍵的問題：「當我們做好了一份漂亮的 HTML 互動簡報、或者前端網頁專案，到底該如何用最快、最穩定、而且完全免費的方式，發布給所有人瀏覽？」

過去大家可能覺得：「架網站是不是要花錢買主機？要申請網域？還要設定一堆資安憑證？」答案是：完全不用！

💡「只要你的專案在 GitHub 上，GitHub Pages 就能在三分鐘內，免費為你提供全球 CDN 加速與 HTTPS 安全網址！」

大家請看畫面，GitHub Pages 具備三大無可取代的優勢：第一，最速直接發布，只要勾選分支跟根目錄，點一下 Save 就搞定；第二，自帶全球高速 CDN 與 SSL 憑證，不管在哪裡開都極速載入；第三，Git 秒級熱更新，未來本地只要執行 git push，雲端就會自動更新，甚至可以在同一個專案放好幾份不同簡報！

接下來，我將用 4 個最直覺的操作步驟，一步步帶大家親眼見證如何讓網頁秒速上線！

SLIDE 02

步驟 1：開啟專案倉庫，進入 Settings（設定）

⏱️ 建議時間：1.5 分鐘
投影片畫面：專案首頁上方選單，右側齒輪圖示「Settings」高亮標示。
🎭 講者動作與現場身態：手指投影片右側的視窗截圖，特別圈出最右上角的齒輪圖示。提醒學員注意檢查自己是否有專案管理權限與 Public 設定。

好，請大家看第一步：請開啟瀏覽器，登入你的 GitHub 帳號，並進入你放簡報或網頁檔案的儲存庫（Repository）。

在專案首頁頂部，你會看到一排選單標籤：從左邊的 Code、Issues、Pull requests，一路往右看，最右邊有一個帶有齒輪圖示的「Settings」（設定）。請直接點選它！

⚠️「注意：如果你進去專案卻找不到 Settings 分頁，代表你目前帳號只是 Collaborator 甚至是訪客，必須是專案擁有者（Owner）或擁有 Admin 管理員權限才看得到喔！」

另外特別提醒一個很常被問到的細節：GitHub 免費個人帳號對 Public（公開）儲存庫是完全免費、無限制開放 GitHub Pages 的；但如果你把專案設為 Private，免費方案是無法直接開啟 Pages 的，所以請務必確認你的專案倉庫是 Public 狀態！

SLIDE 03

步驟 2：在左側選單點選「Pages」

⏱️ 建議時間：1 分鐘
投影片畫面：Settings 左側功能清單，在「Code, planning, and automation」分組下高亮「Pages」。
🎭 講者動作與現場身態：引導大家視線看向左側導覽目錄，口吻輕鬆清晰，強調選單層級結構。

點進 Settings 之後，畫面左側會出現非常長的一排功能清單。請大家往下拉一點點，找到一個叫作 「Code, planning, and automation」（程式碼、規劃與自動化）的大標題。

在這個分組底下，你會看到 Branches、Tags、Actions，再往下看，有一個帶有網頁小視窗圖示的項目，叫做「Pages」。請不要猶豫，直接點下去！

📄「點進 Pages，我們就正式進入了 GitHub Pages 的專屬部署控制台！」

這時候畫面中央就會出現完整的「GitHub Pages」設定頁面，我們所有的發布來源、網域綁定跟上線狀態，全部都在這裡統一掌控。

SLIDE 04

步驟 3：設定 Build and deployment（來源與分支）

⏱️ 建議時間：2 分鐘
投影片畫面：Source 下拉選單「Deploy from a branch」，分支選「main」，目錄選「/ (root)」，點擊「Save」。
🎭 講者動作與現場身態：放慢語速，這裡是整份教學的「核心精髓」，務必帶大家逐一確認三個欄位的值。

接下來請大家看螢幕，這是最關鍵、也是唯一需要做設定的地方——「Build and deployment」（建置與部署）。

在 Source（來源）這個下拉選單中，通常會有兩種選擇：一種是「Deploy from a branch」（直接以分支發布），另一種是「GitHub Actions」（自動化工作流發布）。

⚡「對於我們目前的 HTML 互動簡報、靜態網頁，『最速做法』就是直接選：Deploy from a branch！」

選定 Deploy from a branch 之後，下方會立刻展開兩個小選單：

第一，Branch（分支）：請選你的主要分支，通常是 main（如果是較早期的儲存庫可能叫 master）。

第二，Folder（目錄）：請保持預設的 / (root)，這代表 GitHub 會直接從專案的根目錄尋找網頁檔案。

最後一步，也是大家最常忘記的一步：請一定要點右邊那個深色的「Save」（儲存）按鈕！只要按下 Save，設定就完成了！

（補充說明：如果是用 Vue、React、Vite 這類需要 npm run build 的前端專案，才會建議選下方的 GitHub Actions 讓雲端自動編譯，但純 HTML/CSS/JS 簡報用 Branch 發布最簡單、最不會出錯！）

SLIDE 05

步驟 4：靜候 1~2 分鐘，網站正式發布成功！

⏱️ 建議時間：1.5 分鐘
投影片畫面：GitHub Pages 頂端出現醒目的綠色成功橫幅與「Your site is live at...」即時網址。
🎭 講者動作與現場身態：面帶微笑安撫台下「按下 Save 後不要慌張」，解釋背景排程概念，並指向綠色橫幅與 Visit site 按鈕。

很多初學者按完 Save 之後，重新整理網頁發現什麼都沒變，就開始慌張：「是不是我設錯了？」

請放心！因為 GitHub 在背後需要指派雲端伺服器幫你打包、配發 SSL 憑證跟全球 CDN 快取，這大約需要 60 秒到 120 秒。

🎉「當你在 1~2 分鐘後重新整理頁面，頂部出現綠色框框寫著『Your site is live at...』，恭喜你，你的網站已經正式向全世界公開上線了！」

大家可以看到，綠色橫幅裡會直接附上這份網站的專屬網址，格式永遠是：
https://<你的帳號名稱>.github.io/<專案儲存庫名稱>/

右邊還有一個 「Visit site」 按鈕，點下去就會直接在瀏覽器新分頁中打開你的專案首頁！是不是非常簡單、優雅？

SLIDE 06

進階實踐：同一個 Repo，如何部署多份不同 HTML 簡報？

⏱️ 建議時間：2 分鐘
投影片畫面：index.html、github-pages-tutorial.html、script.html 三種檔案與對應 URL 的樹狀映射，以及日常 git push 更新工作流。
🎭 講者動作與現場身態：語調轉為專業與啟發性，解答大家心中最常浮現的「那我下一份簡報難道要再開一個 Repo 嗎？」的核心疑問。

很多朋友學到這裡，馬上就會問一個很經典的問題：「講者，我不可能每次做一份新簡報，就去開一個全新的 GitHub Repo 吧？如果我在同一個專案裡想放好幾份不同主題的簡報，該怎麼做？」

這就是靜態網頁託管最強大的地方！大家請看畫面上的檔案與網址對應規則：

第一，如果你在專案根目錄放了名為 index.html 的檔案，它會成為專案的預設首頁，網址最後面只要打專案名稱斜線（.../pirls-reading-1128/）就會自動載入它。

第二，如果你設計了一份新的簡報，取名叫 github-pages-tutorial.html，它就會擁有專屬的獨立網址：
.../pirls-reading-1128/github-pages-tutorial.html！

第三，同理，我們現在這份給報告人看的逐字稿手冊 github-pages-script.html，也是直接接在網址後面就能打開！

🚀「這意味著：同一個 GitHub Repo 可以放無限多個 HTML 頁面，只要檔名不同，每一個頁面都能獨立成為一份線上簡報或教學手冊！」

而且最棒的是日常維護工作流：日後你只要在本地修改檔案，終端機執行三行指令：git add .、git commit -m "update"、git push origin main，完全不需要再進 GitHub 後台點任何按鈕，GitHub Pages 就會秒級自動熱更新！

SLIDE 07

總結速查與常見排錯 CheckList

⏱️ 建議時間：1.5 分鐘
投影片畫面：4 步極速上線口訣、常見排錯 Q&A（404 處理、快取問題），以及本專案所有成果直達連結。
🎭 講者動作與現場身態：帶領大家進行最後的記憶固化，用口訣帶過重點，並主動說明最容易踩坑的「404」與「瀏覽器快取」問題，為整場分享劃下完美句點。

最後，我們用一分鐘來幫大家做個總結記憶。請大家在心裡跟我一起覆誦這四步口訣：

📋「一進 Settings 齒輪 ➔ 二選 Pages 標籤 ➔ 三設 Deploy from a branch (main + /root) ➔ 四點 Save 大功告成！」

另外，當你日後遇到問題時，請優先檢查這三個最常見的狀況：

第一，按下 Save 沒看到綠色橫幅？請別急，點頂部「Actions」分頁看建置進度，等黃色圈圈轉成綠色勾勾就完成了。

第二，點開網址出現 404 Not Found？請檢查網址英文字母大小寫有沒有打錯（GitHub Pages 是嚴格區分大小寫的），或者確認所選的 branch 確實有包含你的 html 檔案。

第三，本地 push 後線上好像沒變？通常是瀏覽器暫存快取，請按下 Ctrl + F5 強制重新整理，或用無痕視窗開啟即可！
